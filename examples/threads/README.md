# Threads example

[`main.server.js`](main.server.js) uses [`@reactc/threads`](../../packages/reactc-threads/README.md).
It shows Java-style threads (a `Thread` subclass), functional ones (`spawn`,
`parallel`), a `Map` shared and updated by several threads under
`synchronized`, and an error thrown on a thread that `join()` rethrows.

## Build and run

From the repository root on Windows:

```sh
compiler/target/debug/reactc.exe build examples/threads/main.server.js --target windows --name ThreadsDemo --outdir dist/threads-demo
dist/threads-demo/ThreadsDemo.exe
```

For Linux, use `--target host` and run the result in WSL. With the packaged
compiler, run `reactc build …` instead.

Output:

```json
{
  "primesBelow500k": { "javaStyle": 41538, "functional": 41538, "inQuarters": 41538 },
  "wordCounts": { "a": 1, "cat": 2, "dog": 1, "end": 1, "ran": 2, "sat": 1, "the": 3 },
  "threadsThatReadText": 4,
  "caught": "RangeError: bad input on a thread"
}
```

## Use it in your own project

1. Put your server code in a server file (a `.server.js`/`.server.ts` file,
   the configured `server` folder, or build it with `--server`).
2. `import { Thread, spawn, parallel, synchronized } from '@reactc/threads';`
   (`'reactc:threads'` also works). In a project generated by `reactc new`,
   add `"@reactc/threads": "file:<reactc>/packages/reactc-threads"` to
   `devDependencies` for editor types.
3. Build with reactc as usual. The import switches the build to the shared
   heap, and the build log says `shared heap: …/app.c`.

```js
import { Thread, spawn, parallel, synchronized } from '@reactc/threads';

class Job extends Thread {             // Java style
  constructor(input) { super(); this.input = input; }
  run() { return heavyWork(this.input); }
}
const job = new Job(42).start();
const answer = job.join();

const total = spawn(heavyWork, 7).join();                // functional style
const all = parallel([1, 2, 3, 4], n => heavyWork(n));   // one thread each

const seen = new Set();                                  // shared between threads
parallel(items, item => synchronized(seen, () => seen.add(item.id)));
```

`run()` can be `async` and use timers and I/O, and a thread is a promise:
`await spawn(fn)`, `Promise.all([threadA, threadB])`. See the package README
for the details and limits.

## Async example

[`async.server.js`](async.server.js) shows await with threads:
- an async `run()` that writes, waits and reads a file on its own event loop
- `await spawn(...)`
- `Promise.all` and `Promise.race` over threads
- `try`/`await`/`catch` for errors
- the main thread's timer still ticking while threads work

```sh
compiler/target/debug/reactc.exe build examples/threads/async.server.js --target windows --name AsyncThreads --outdir dist/async-example
dist/async-example/AsyncThreads.exe
```

```
1. await spawn(...)            -> 17984 primes below 200000 (56 ms)
2. Promise.all([threads])      -> north: 3 lines | south: 2 lines (123 ms)
3. try { await thread }        -> caught "disk full"
4. Promise.race([threads])     -> fast thread (178 ms)
5. main timer ticked 23 times while 4 threads worked (300 ms)
```

`node scripts/check-reactc-shared-threads.mjs [reactc.exe] [--host]` builds
this example and the stress tests, and checks them on Windows and Linux.
